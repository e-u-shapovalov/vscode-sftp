## Скачивание и установка

### Что скачивать?

Установите WireFerry из [Visual Studio Code Marketplace](https://marketplace.visualstudio.com/items?itemName=EvgeniiShapovalov.wireferry). Для offline/ручной установки скачайте `wireferry-<version>.vsix` из блока **Assets** на странице [последнего GitHub Release](https://github.com/e-u-shapovalov/vscode-sftp/releases/latest).

> **Если вы обычный пользователь, не нажимайте `Code → Download ZIP`. Скачайте готовый пакет расширения со страницы GitHub Releases.**

`Source code (zip)`, `Source code (tar.gz)` и **Code → Download ZIP** — архивы исходников для разработчиков. Это не устанавливаемый пакет расширения.

### Как установить из Marketplace?

В настольном VS Code откройте **Extensions / Расширения** (`Ctrl+Shift+X`), найдите `WireFerry` и нажмите **Install / Установить**. Дальнейшие обновления из Marketplace VS Code установит автоматически, если включено автообновление расширений.

### Как установить VSIX?

В настольном VS Code откройте **Extensions / Расширения** (`Ctrl+Shift+X`), выберите **... → Install from VSIX... / Установить из VSIX...** и укажите скачанный файл.

Если доступна команда VS Code `code`:

```bash
code --install-extension wireferry-<version>.vsix
```

Не распаковывайте `.vsix`.

### Я случайно скачал Source code. Можно превратить его в VSIX?

Не переименовывайте ZIP. Вернитесь к [последнему релизу](https://github.com/e-u-shapovalov/vscode-sftp/releases/latest) и скачайте `.vsix` из блока **Assets**.

Разработчик может собрать пакет из исходников через `npm ci`, `npm run compile` и `npx @vscode/vsce package`, но обычному пользователю нужен опубликованный asset.

## Настройка и конфигурация

### Не появились команды WireFerry или дерево сервера

Проверьте:

- расширение установлено и включено;
- запущен настольный VS Code 1.66 или новее;
- открыта папка проекта, а не только отдельный файл;
- workspace является доверенным;
- `.vscode/wireferry.json` или legacy-файл `.vscode/sftp.json` корректен.

Перезагрузите VS Code и выполните **WireFerry: Config**. Меню передачи недоступны, пока корректная конфигурация не загружена.

### `Config Not Found`

WireFerry не смог сопоставить выбранный локальный файл с загруженной конфигурацией. Частые причины:

- открыта не та папка workspace;
- конфиг находится не в каталоге `.vscode` открытого workspace;
- `context` указывает на другую локальную подпапку;
- выбранный файл лежит вне настроенного `context`.

Откройте корень проекта и проверьте `.vscode/wireferry.json` и `context`.

### Какой файл конфигурации использовать?

Для новых проектов используйте `.vscode/wireferry.json`. WireFerry также читает legacy-файл `.vscode/sftp.json` и может предложить переименовать его.

Формат — JSONC: разрешены комментарии и завершающие запятые. VS Code проверяет известные поля по встроенной схеме.

### Как выгружать содержимое папки, но не саму папку?

Задайте эту локальную папку в `context`, а каталог назначения — в `remotePath`. Например, такой конфиг сопоставляет содержимое `build` напрямую с `/var/www/site`:

```json
{
  "name": "Production",
  "host": "example.com",
  "protocol": "sftp",
  "port": 22,
  "username": "deploy",
  "password": "prompt",
  "context": "./build",
  "remotePath": "/var/www/site"
}
```

### Как скачать существующий проект с сервера?

1. Откройте в VS Code пустую локальную папку.
2. Выполните **WireFerry: Config** и укажите правильный путь на сервере.
3. Выполните **WireFerry: Download Project**.

Перед работой с важными данными сделайте резервную копию и проверьте `context`, `remotePath`, исключения и параметры синхронизации.

## Авторизация и проблемы подключения

### Как хранить пароль?

Используйте один из вариантов:

- `"password": "secretStorage"` — хранить и читать пароль через VS Code SecretStorage;
- `"password": "prompt"` — спрашивать при каждом подключении без сохранения;
- обычная строка — поддерживается, но хранится открытым текстом в файле проекта.

Для SFTP по возможности используйте SSH-ключ. Поле `privateKeyPath` задаёт ключ; для зашифрованного ключа в `passphrase` можно указать `true` или `"secretStorage"`. Не коммитьте секреты открытым текстом.

### SFTP-соединение закрывается или появляется `Unknown DH group`

Старому SSH-серверу может требоваться устаревший алгоритм обмена ключами или ключ хоста. Добавляйте только тот алгоритм, который подтвердил администратор сервера. Например:

```json
{
  "algorithms": {
    "kex": {
      "append": ["diffie-hellman-group1-sha1"]
    },
    "serverHostKey": {
      "append": ["ssh-rsa"]
    }
  }
}
```

Не копируйте этот пример во все конфиги: устаревшие алгоритмы снижают безопасность соединения и нужны только для серверов, которые нельзя обновить.

### Сервер сообщает `Permission denied`

Проверьте, что настроенный пользователь может писать в `remotePath` и в целевой файл или каталог.

Для SFTP WireFerry может предложить сохранить изменённую копию во временный доступный путь на сервере. На совместимом SSH-сервере копию можно применить через `su`; для этого нужны работающая команда `su` и корректные данные root. На FTP такое восстановление недоступно.

### Папка жёлтая или я не могу прочитать root-овый файл

Remote Explorer подсвечивает папку **жёлтым**, когда у вашего логина нет прав её листать. Нажмите ПКМ и выберите **View / list as root**, затем введите пароль владельца или root: WireFerry покажет папку на месте либо откроет нечитаемый файл как одноразовую копию только для чтения — через `su`. Нужно подключение SFTP/SSH — у FTP нет shell — и пароль хранится только в памяти. См. [Доступ от root](docs/commands.RU.md#доступ-от-root-просмотр-листинг-и-удаление).

### Сервер сообщает `Error: Failure`

Это общий статус SFTP, у которого нет одной универсальной причины. Проверьте:

- существует ли удалённый путь;
- права файла и каталога;
- квоту и свободное место на сервере;
- ограничения на имена файлов;
- лимиты соединений и каналов.

Включите отладочные логи и откройте **View / Вид → Output / Вывод → WireFerry**. Если сервер ограничивает число одновременных операций, уменьшите `concurrency`. Используйте `limitOpenFilesOnRemote` только тогда, когда подтверждён серверный лимит файловых дескрипторов.

## Передача и синхронизация

### На сервер выгружаются лишние файлы

Задайте gitignore-совместимые шаблоны в `ignore`:

```json
{
  "ignore": [
    ".vscode",
    ".git",
    "node_modules",
    "*.log",
    "*.tmp"
  ]
}
```

Чтобы читать шаблоны из файла, укажите его явно:

```json
{
  "ignoreFile": ".gitignore"
}
```

`remoteExplorer.filesExclude` влияет только на отображение дерева и не исключает файлы из передачи.

### Может ли WireFerry автоматически выгружать изменения?

Для файлов, сохранённых в VS Code:

```json
{
  "uploadOnSave": true
}
```

Для файлов, которые меняют внешние программы:

```json
{
  "uploadOnSave": false,
  "watcher": {
    "files": "**/*",
    "autoUpload": true
  }
}
```

Не включайте `uploadOnSave` и `watcher.autoUpload` для одних файлов, если повторные выгрузки нежелательны.

### Может ли синхронизация удалять файлы?

Да. `syncOption.delete` может удалять в приёмнике файлы, которых нет в источнике. Источник и приёмник меняются вместе с выбранным направлением синхронизации.

Перед включением удаления проверьте `context`, `remotePath`, активный профиль и исключения. Сначала протестируйте конфиг на некритичных данных и сохраните резервную копию.

### Почему WireFerry просит напечатать `yes` перед удалением?

Удаление на сервере, после которого не останется безопасной копии, сначала просит напечатать `yes`. WireFerry пропускает этот запрос только когда у выбранного элемента есть идентичная локальная копия, подтверждённая совпадением размера и MD5. Удаление с обеих сторон или со всех профилей спрашивает всегда. Серверы без серверного инструмента MD5 — включая FTP — проверить нельзя, поэтому там запрос появляется всегда. См. [Безопасное удаление](docs/commands.RU.md#безопасное-удаление).

### Почему FTP передаёт только один файл за раз?

WireFerry принудительно устанавливает для FTP concurrency, равный `1`. Параметр `concurrency` действует для других режимов передачи, но не меняет это поведение FTP.

### Исправляет ли `remoteTimeOffsetInHours` разницу времени?

Сейчас нет. Поле присутствует в схеме, но конвейер передачи его не применяет. Не рассчитывайте на него при оценке безопасности синхронизации.

## Диагностика

### Как включить отладочные логи?

Установите `wireferry.debug` в `true` в настройках VS Code, перезагрузите окно и откройте **View / Вид → Output / Вывод → WireFerry**.

Перед публикацией логов удалите пароли, имена пользователей, хосты и чувствительные пути.

### Куда сообщать о воспроизводимой проблеме?

Создайте [GitHub Issue](https://github.com/e-u-shapovalov/vscode-sftp/issues) и укажите:

- версии WireFerry и VS Code;
- протокол и относящиеся к проблеме поля конфига без секретов;
- точные шаги воспроизведения;
- полный текст ошибки;
- очищенный от чувствительных данных debug-лог, если он есть.

## Происхождение проекта

### WireFerry — это оригинальное расширение `vscode-sftp`?

Нет. WireFerry — независимо поддерживаемый fork, который не выдаёт себя за оригинальное расширение. Происхождение: Natizyskunk/vscode-sftp ← liximomo/vscode-sftp; этот fork начат с upstream `v1.16.3` и теперь использует другое имя и другого издателя.

### Есть ли отдельное приложение или CLI WireFerry?

Нет. WireFerry работает внутри настольного Visual Studio Code. Необязательная команда `code --install-extension` принадлежит VS Code и только устанавливает пакет.
