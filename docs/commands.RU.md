# Справочник команд WireFerry

[English version](commands.md) · [Основной README](../README.RU.md) · [Конфигурация](configuration.RU.md) · [FAQ](../FAQ.RU.md)

Откройте палитру команд через `Ctrl+Shift+P` и введите `WireFerry`. Многие команды передачи также доступны в контекстных меню локального Explorer, редактора, Source Control и Remote Explorer.

Команды, которым нужен сервер, становятся доступны после загрузки корректного `.vscode/wireferry.json` или legacy-файла `.vscode/sftp.json`.

## Настройка и подключение

| Команда | Назначение |
| --- | --- |
| `WireFerry: Config` | Запустить мастер, если конфига нет, или открыть текущий конфиг |
| `WireFerry: Set Profile` | Выбрать активный профиль для команд без явного контекста профиля |
| `WireFerry: Open SSH in Terminal` | Открыть SSH-терминал для текущего SFTP-подключения |
| `WireFerry: Check for Updates` | Попросить VS Code проверить обновления расширений в Marketplace и открыть страницу WireFerry |
| `WireFerry: Open Extension Page` | Открыть страницу расширения в VS Code |
| `WireFerry: Cancel All Transfers` | Остановить текущие выгрузки и скачивания |

`Open SSH in Terminal` работает только для конфигураций SFTP/SSH.

## Выгрузка

| Команда | Назначение |
| --- | --- |
| `Upload File` | Выгрузить выбранный локальный или сопоставленный файл |
| `Upload Active File` | Выгрузить открытый в редакторе файл |
| `Upload Folder` | Выгрузить выбранную папку |
| `Upload Active Folder` | Выгрузить папку активного файла |
| `Upload Project` | Выгрузить всё внутри настроенного `context` |
| `Force Upload` | Выгрузить без учёта ignore; альтернативное действие контекстного меню |
| `Upload Changed Files` | Применить на сервере добавления, изменения и переименования из Git working tree/index; перед удалениями задаётся вопрос |

Сочетание по умолчанию для **Upload Changed Files** — `Ctrl+Alt+U`.

Если настроены `profiles`, у команд выгрузки файла, активного файла, папки, активной папки, проекта и force-upload есть варианты **To All Profiles / Во все профили**.

## Скачивание

| Команда | Назначение |
| --- | --- |
| `Download File` | Скачать выбранную удалённую версию с заменой сопоставленного локального файла |
| `Download Active File` | Скачать удалённую версию активного локального файла |
| `Download Folder` | Скачать выбранную папку |
| `Download Active Folder` | Скачать папку активного файла |
| `Download Project` | Скачать настроенный удалённый проект |
| `Force Download` | Скачать без учёта ignore; альтернативное действие контекстного меню |

Передача может перезаписать существующие файлы. Сначала проверьте `context`, `remotePath`, выбранный профиль и исключения.

## Синхронизация и сравнение

| Команда | Назначение |
| --- | --- |
| `Sync Local -> Remote` | Использовать локальное дерево как источник, а сервер как приёмник |
| `Sync Remote -> Local` | Использовать сервер как источник, а локальное дерево как приёмник |
| `Sync Both Directions` | Сравнить время изменения и поместить более новую версию на обе стороны |
| `Diff with Remote` | Сравнить выбранный локальный файл с удалённой копией |
| `Diff Active File with Remote` | Сравнить активный файл редактора с удалённой копией |
| `List` | Показать удалённую папку и выбрать файл |
| `List Active Folder` | Показать удалённую папку, соответствующую папке активного файла |
| `List All` | Показать удалённые файлы, доступные ниже `remotePath` |

`syncOption` управляет созданием, обновлением и удалением. Проверьте его перед синхронизацией важных данных. Для **Sync Both Directions** применяются только `skipCreate` и `ignoreExisting`.

### Маркеры статусов в дереве

Remote Explorer показывает **один объединённый элемент на файл**, совмещая локальную и серверную копии. Локальные файлы появляются сразу; серверная сторона подгружается чуть позже (в статус-баре при этом видно *WireFerry: loading the server listing…*). Пометка показывает, как соотносятся обе стороны:

| Пометка | Значение |
| --- | --- |
| `L` | **Только локально** — файл есть на диске, но ещё не выгружен на сервер |
| `M` | **Изменён** — локальная и серверная копии различаются (по размеру или времени изменения) |
| `!` | **Конфликт** — с одной стороны файл, с другой папка |
| `?` | **Неизвестно** — не удалось прочитать листинг сервера (временная ошибка или отказ по правам на FTP) |
| жёлтый, без буквы | **Нет доступа** — папку не разрешено листать; ПКМ → **View / list as root** |
| `RO` | **Только чтение** — у вас нет прав на запись этого файла |

Файлу «в синхроне» или серверному файлу без пометки маркер не нужен.

Одиночный клик **сразу открывает локальную копию**, если она есть — мгновенно, ничего не скачивая и не перезаписывая. Для файла, который есть только на сервере, клик скачивает и открывает его либо показывает read-only preview — в зависимости от `wireferry.downloadWhenOpenInRemoteExplorer` (ниже); для symlink предлагается открыть его цель.

При `wireferry.downloadWhenOpenInRemoteExplorer: true` клик по файлу, который есть только на сервере, скачивает его с progress и затем открывает. При `false` WireFerry открывает read-only preview. Включите **Show Sizes**, чтобы видеть размеры в дереве; у изменённого файла показываются обе стороны как `server ↔ local`.

Размер папки считается серверной командой `du`, если она доступна по SFTP; иначе WireFerry обходит удалённое дерево. Серверный MD5 требует подходящих shell-команд и недоступен на FTP.

`Show Tree…` сначала спрашивает, как рисовать дерево (только папки, с файлами или с файлами и размерами) и максимальную глубину (пусто или `0` — без ограничения). Дерево открывается в текстовой вкладке и обрывается на 20000 записях для очень больших папок. Команда доступна на папках и в Remote Explorer, и в локальном Explorer.

Также можно **перетаскивать** элементы внутри Remote Explorer, чтобы переместить или переименовать их на сервере; соответствующая локальная копия обновляется после подтверждения. Перемещение идёт в пределах одного соединения — перетаскивание между разными профилями не выполняется.

## Управление удалёнными файлами

| Команда | Назначение |
| --- | --- |
| `Create File` / `Create Folder` | Создать элемент внутри выбранной удалённой папки |
| `Rename` | Переименовать или переместить выбранный удалённый элемент |
| `Delete (server / local / both)…` | Выбрать удаление на сервере, локально или с обеих сторон |
| `Change Permissions (chmod)` | Изменить Unix-права; папку можно обработать рекурсивно |
| `Change Owner / Group (chown, as root)` | Выполнить `chown` через `su` на совместимом SSH-сервере |

Новые файлы и папки, созданные прямо в дереве, берут права из `filePerm` / `dirPerm`, если они заданы (см. [справочник конфигурации](configuration.RU.md#общие-поля)).

### Безопасное удаление

Окно удаления предлагает **On server** (на сервере), **On computer** (локально), **On both** (с обеих сторон) и — если в конфиге есть профили — **All servers + computer** (со всех серверов и локально). Удалённая локальная копия перемещается в Корзину ОС, а не стирается; если Корзина недоступна (например, на некоторых сетевых или subst-дисках), WireFerry переходит к безвозвратному удалению и предупреждает об этом.

Когда удаление на сервере не оставит безопасной копии, WireFerry просит ввести **`yes`** для подтверждения. Этот запрос пропускается только если у каждого выбранного элемента есть идентичная локальная копия, подтверждённая совпадением **размера и MD5**; удаление **On both** или **All servers + computer** спрашивает всегда. Серверы без серверного инструмента MD5 (включая FTP) проверить нельзя, поэтому там подтверждение появляется всегда.

### Доступ от root: просмотр, листинг и удаление

Некоторые пути на Unix-сервере принадлежат `root` или другому пользователю и недоступны вашему логину для чтения или удаления. WireFerry может работать с ними через `su` и только по **SFTP/SSH** — у FTP нет shell, поэтому там эти действия отклоняются. Доступ — из ПКМ по любому файлу или папке в Remote Explorer; папка, которую нельзя листать, дополнительно подсвечивается **жёлтым** с подсказкой *нет доступа — ПКМ View as root*.

![Контекстное меню Remote Explorer на root-owned папке — жёлтая строка «нет доступа» и команды WireFerry, включая «View / list as root…».](../assets/showcase/root-access-context-menu.png)

| Команда | Назначение |
| --- | --- |
| `View / list as root…` | Показать папку, которую нельзя прочитать, или открыть нечитаемый файл только для чтения |
| `Delete as root` | Предлагается автоматически, когда обычное удаление отклонено по правам; выполняет `rm -rf` от root после подтверждения |

- **View / list as root** сначала спрашивает, действовать ли от имени владельца файла (предлагается, когда это безопасно) или от `root`, затем запрашивает пароль этой учётной записи. Папка листается на месте жёлтой строки; файл открывается как одноразовая копия только для чтения — предполагается текст, поэтому бинарный файл может выглядеть искажённо — и удаляется при закрытии.
- **Delete as root** появляется только после удаления, отклонённого по правам. Он перечисляет точные пути, всегда просит подтверждение (даже если пароль уже в кэше) и отказывается работать на `/`. При удалении **On both** локальная копия всё равно перемещается в Корзину.
- Привилегированный повтор `chmod` и `Change Owner / Group (chown, as root)` используют тот же механизм. Пароль для повышения прав хранится **только в памяти**, привязан к реальному хосту, порту и учётной записи соединения; он никогда не пишется на диск, в конфиг или в лог и сбрасывается при перезагрузке окна VS Code.

## Учётные данные

| Команда | Назначение |
| --- | --- |
| `Generate SSH Key…` | Создать SSH-ключ, развернуть публичную часть и переключиться после проверенного входа |
| `Save Password to Keychain…` | Сохранить пароль через VS Code SecretStorage и обновить конфиг |
| `Delete Saved Password…` | Удалить выбранные пароли или passphrase из SecretStorage |

Создание SSH-ключа доступно только для SFTP. Хранение пароля работает для основных конфигураций и профилей; учётные данные jump host в SecretStorage не сохраняются.

## Отчёты об операциях

После выгрузки, скачивания или удаления по правому клику WireFerry открывает вкладку `upload.log`, `download.log` или `delete.log` со списком файлов, их размером, датой изменения и правами, а также итогом «N успешно, M с ошибкой». Для удаления также показано, где расходятся локальная и серверная копии, а при нескольких профилях каждая строка помечена своим сервером.

## Интеграция с локальным Explorer

Контекстное меню локального Explorer содержит действия выгрузки, скачивания, синхронизации, diff, удаления, Size & MD5 и Show Tree для сопоставленных элементов.

`Copy Path (Git Bash)` преобразует выбранные Windows-пути вида `C:\project\file` в формат Git Bash `/c/project/file`.

Локальное переименование или перемещение можно после подтверждения применить на сервере. Удаление через VS Code также можно после подтверждения повторить на сервере; внешние изменения файловой системы не вызывают эти два обработчика подтверждения.
