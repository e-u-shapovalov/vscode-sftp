# WireFerry — синхронизация по SFTP, FTP и FTPS в Visual Studio Code

**WireFerry — расширение VS Code для загрузки, скачивания, сравнения и синхронизации файлов с удалёнными серверами.** Оно добавляет в редактор SFTP/FTP-клиент, выгрузку при сохранении и проводник файлов на сервере, чтобы обновлять сайт, VPS или staging без постоянного переключения на отдельную программу.

[English version](README.md) · [Установка](INSTALL.md#русский) · [Настройка](docs/configuration.md) · [FAQ](FAQ.md) · [История изменений](CHANGELOG.md)

## Скачать и установить

Готовые выпуски WireFerry распространяются через GitHub Releases в виде пакета расширения для Visual Studio Code.

**Скачайте [`wireferry-<version>.vsix` из последнего релиза](https://github.com/e-u-shapovalov/vscode-sftp/releases/latest).**

> **Если вы обычный пользователь, не нажимайте `Code → Download ZIP`. Скачайте готовый пакет расширения со страницы GitHub Releases.**

Если вы раньше не пользовались GitHub:

1. Откройте страницу [последнего релиза](https://github.com/e-u-shapovalov/vscode-sftp/releases/latest).
2. Найдите блок **Assets**.
3. Скачайте файл `wireferry-<version>.vsix`. Архивы **Source code** скачивать не нужно.
4. В VS Code откройте **Extensions / Расширения** (`Ctrl+Shift+X`).
5. Нажмите **...** в правом верхнем углу панели и выберите **Install from VSIX... / Установить из VSIX...**.
6. Укажите скачанный `.vsix` и перезагрузите VS Code, если редактор попросит.

`.vsix` не нужно распаковывать. У WireFerry нет отдельного установщика или самостоятельной программы. Подробная инструкция и решение проблем при установке находятся в [INSTALL.md](INSTALL.md#русский).

## Быстрый старт

1. Откройте в VS Code локальную **папку** проекта.
2. Нажмите `Ctrl+Shift+P` и выполните **WireFerry: Config**.
3. Пройдите мастер настройки: выберите протокол, укажите сервер, порт, пользователя, удалённый путь и способ авторизации.
4. Мастер проверит подключение и создаст `.vscode/wireferry.json`.
5. Выгружайте, скачивайте, сравнивайте и синхронизируйте файлы через палитру команд, контекстное меню или Remote Explorer.

Мастер поддерживает SFTP и FTP. Старые конфиги `.vscode/sftp.json` продолжают работать как legacy-формат.

## Основные возможности

- Выгрузка и скачивание файла, папки, активного файла или всего настроенного проекта.
- Синхронизация в направлениях локально → сервер, сервер → локально и в обе стороны.
- Выгрузка при сохранении и наблюдение за внешними изменениями файлов.
- Сравнение локального файла с версией на сервере.
- Remote Explorer с деревом файлов сервера внутри VS Code.
- Создание, переименование, перенос и удаление удалённых файлов и папок.
- Несколько профилей для development, staging и production.
- Выгрузка во все профили, если файлы должны попасть на несколько серверов.
- SFTP/SSH, FTP, FTPS и локальное зеркало через протокол `local`.
- Подключение к SFTP через промежуточные SSH-хосты.
- SSH-ключи, запрос пароля при подключении и хранение секретов через VS Code SecretStorage.

![Remote Explorer в WireFerry](assets/showcase/remote-explorer-overview-2.5.4.png)

WireFerry подходит для поддержки сайтов, shared-хостинга, VPS и других задач, где файлы нужно передавать прямо из рабочего пространства VS Code. Это не замена CI/CD и не система управления релизами.

## Конфигурация

Настройки проекта хранятся в `.vscode/wireferry.json`. Это JSON с поддержкой комментариев; VS Code показывает подсказки и проверяет поля по встроенной схеме.

Минимальный конфиг SFTP при ручном редактировании:

```json
{
  "name": "Production",
  "host": "example.com",
  "protocol": "sftp",
  "port": 22,
  "username": "deploy",
  "password": "prompt",
  "remotePath": "/var/www/site",
  "uploadOnSave": false
}
```

`context` задаёт локальную папку, а `remotePath` — соответствующую папку на сервере. Перед первой массовой передачей проверьте `ignore`, чтобы не отправить локальные служебные файлы.

Все поля, профили и примеры SFTP/FTP описаны в [руководстве по конфигурации](docs/configuration.md).

## Частые команды

Откройте палитру через `Ctrl+Shift+P` и введите `WireFerry`.

| Команда | Назначение |
| --- | --- |
| `WireFerry: Config` | Запустить мастер или открыть существующий конфиг |
| `WireFerry: Upload Active File` | Выгрузить открытый файл |
| `WireFerry: Upload Changed Files` | Выгрузить изменённые в Git файлы; сочетание по умолчанию `Ctrl+Alt+U` |
| `WireFerry: Upload Project` | Выгрузить всё внутри настроенного `context` |
| `WireFerry: Download Project` | Скачать настроенный удалённый проект |
| `WireFerry: Sync Local -> Remote` | Синхронизировать локальную папку на сервер |
| `WireFerry: Sync Remote -> Local` | Синхронизировать серверную папку на компьютер |
| `WireFerry: Sync Both Directions` | Перенести более новые файлы в обе стороны |
| `WireFerry: Diff Active File with Remote` | Сравнить открытый файл с удалённой копией |
| `WireFerry: Open SSH in Terminal` | Открыть SSH-сессию для настроенного SFTP-сервера |

Полный список находится в [docs/commands.md](docs/commands.md).

## Авторизация и безопасность

- Для SFTP по возможности используйте SSH-ключ.
- `"password": "secretStorage"` хранит пароль через VS Code SecretStorage, а не в проекте.
- `"password": "prompt"` спрашивает пароль при каждом подключении и не сохраняет его.
- Обычная строка в поле `password` лежит в конфиге открытым текстом — не коммитьте такой файл.
- Перед синхронизацией с удалением проверьте `context`, `remotePath`, `ignore` и `syncOption`.
- Расширению требуется доверенное рабочее пространство VS Code.

В контекстном меню сервера есть команды для создания SSH-ключа, сохранения пароля и удаления сохранённых учётных данных.

## Ограничения

- Требуется Visual Studio Code 1.66 или новее.
- WireFerry работает внутри настольного VS Code; отдельного GUI или собственного CLI нет.
- `remoteTimeOffsetInHours` есть в схеме, но сейчас не применяется при передаче файлов.
- Для FTP значение `concurrency` принудительно равно `1`.
- Одновременные `uploadOnSave` и `watcher.autoUpload` для одних файлов могут вызвать повторную выгрузку.
- Параметры `syncOption` могут разрешать перезапись и удаление. Сначала проверяйте новую конфигурацию на некритичных данных.

Известные ошибки и технический долг перечислены в [ROADMAP.md](ROADMAP.md).

## Устранение проблем

### Команды WireFerry не появились

Проверьте, что расширение установлено и включено, открыта доверенная папка проекта, а в ней есть `.vscode/wireferry.json` или старый `.vscode/sftp.json`. Создать конфиг можно командой **WireFerry: Config**.

### `Config Not Found`

Откройте корневую папку проекта, а не отдельный файл. Конфиг должен находиться внутри открытой папки, а текущий файл — внутри настроенного `context`.

### Файлы попадают не в ту папку

Проверьте пару `context` и `remotePath`: это локальный и удалённый корни, которые WireFerry сопоставляет друг с другом.

### На сервер ушли лишние файлы

Добавьте в `ignore` шаблоны `.git`, `node_modules`, `*.log` или укажите подходящий файл в `ignoreFile`.

### Нужны подробные логи

Включите `wireferry.debug` в настройках VS Code, перезагрузите окно и откройте **View / Вид → Output / Вывод → WireFerry**. Дополнительные решения для SFTP, старых SSH-серверов и ignore-правил собраны в [FAQ.md](FAQ.md).

## Разработчикам

Проект написан на TypeScript и собирается Webpack. Entry point — `src/extension.ts`, результат — `dist/extension.js`. Точная минимальная версия Node.js/npm в проекте не объявлена; используйте актуальный поддерживаемый выпуск Node.js.

```bash
git clone https://github.com/e-u-shapovalov/vscode-sftp.git
cd vscode-sftp
npm install
npm run compile
npm test
npx tsc --noEmit
```

Режим пересборки при изменениях:

```bash
npm run dev
```

Собрать и установить локальный пакет:

```bash
npx @vscode/vsce package
code --install-extension wireferry-<version>.vsix
```

Дополнительные проверки описаны в [CONTRIBUTING.md](CONTRIBUTING.md).
